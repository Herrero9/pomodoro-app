# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project overview

An Ionic + Angular Pomodoro timer app (Spanish-language UI), buildable as a web app (deployed to GitHub Pages) and as an Android app via Capacitor.

## Commands

- `npm start` / `ng serve` — run the dev server.
- `npm run build` / `ng build` — production build, output goes to `www/` (see `outputPath` in [angular.json](angular.json)).
- `npm test` / `ng test` — run unit tests via the `@angular/build:unit-test` builder (Vitest under the hood, jsdom environment, setup file `src/test-setup.ts`).
  - To run a single spec file: `ng test -- src/app/home/home.page.spec.ts` (Vitest filename filtering applies since the builder passes through to Vitest).
- `npm run lint` / `ng lint` — ESLint via `@angular-eslint/builder`, lints `src/**/*.ts` and `src/**/*.html` (flat config in [eslint.config.js](eslint.config.js)).
- `ng build --base-href /pomodoro-app/` — the exact production build command used by the GitHub Pages deploy workflow ([.github/workflows/deploy-pages.yml](.github/workflows/deploy-pages.yml)); pushes to `main` trigger this automatically.

There is no separate `www/` source — it is a build artifact and is gitignored.

## Architecture

**Module structure**: Classic Angular NgModules (not standalone components) — `standalone: false` is set explicitly on every component/page because the Ionic schematics default to standalone. `AppModule` bootstraps `AppComponent` and imports `AppRoutingModule`, which lazy-loads two feature modules by route: `home` (`/home`) and `settings` (`/settings`). Root redirects to `/home`.

**State lives in root-provided services**, consumed directly by components via Angular signals — there is no NgRx/store layer:
- [`TimerService`](src/app/services/timer.service.ts) — the core pomodoro state machine, and the single source of truth for anything the UI shows about the timer. Holds `settings`, `phase` (`work` | `shortBreak` | `longBreak`), `secondsRemaining`, `isRunning`, `workPeriodsCompleted`, `completedPeriods` and `task` as signals; every derived value components need is a `computed()` here rather than a getter in a component — `progress`, `isBreak`, `nextPhase`, `phaseLabel`, `nextPhaseLabel`, `nextPhaseSummary`, `currentCycle`, `cycleDots`, `workPeriodsToday`, `focusMinutesToday`, `headline`. Commands (`start`/`pause`/`toggle`/`reset`/`skip`/`applyPreset`/`updateSettings`/`setTask`/`clearHistory`) live here too, so components stay declarative. Ticks via `rxjs interval(1000)` but counts down against a stored `deadline` timestamp, so a throttled or delayed interval does not lose time. `nextPhase` drives both the "next up" label and the actual transition in `advancePhase`, keeping the long-break cadence (`settings.sessionsBeforeLongBreak`) defined once. Async-restores state on construction; consumers that need restored state to be in place should `await timer.ready` first (see `SettingsPage.ngOnInit`).

  Three invariants are worth knowing before editing it:
  - **`phaseDurationSeconds` is a signal, not a derivation of `settings`.** Changing a duration mid-period (a preset shortcut, a save in Ajustes) must not resize the period already counting down — that pushed `progress` outside 0–1 and broke the ring. New durations are picked up by the *next* phase, or immediately if the clock is paused.
  - **The clock survives a reload.** `persistState()` writes `{phase, secondsRemaining, phaseTotalSeconds, workPeriodsCompleted, isRunning, deadline, task}` under `pomodoro_state` on every transition — never on a tick, since the deadline is what a restore counts against. `resumeFrom()` then replays (up to `MAX_CATCH_UP_PHASES`) every phase that ended while the app was closed, filing each in the history without re-firing its alert, and carries on against what is left of the current one.
  - **`advancePhase` honours the auto-start settings.** When `autoStartBreaks`/`autoStartWork` is off, the next phase is set up at full duration and left paused rather than chaining straight on.
- [`AlertService`](src/app/services/alert.service.ts) — everything the app does to say a phase ended: a synthesised two-note chime (WebAudio, so there is no audio asset to ship or fail to load), `@capacitor/haptics` on device or `navigator.vibrate` on the web, and a system `Notification`. Every one of them is optional and fails quietly. `prime()` is called from `TimerService.start()` because browsers only let an audio context open from a user gesture, never from a timer callback.
- [`PresenceService`](src/app/services/presence.service.ts) — the two things the timer does outside the app's own UI: the countdown in the browser tab title, and the Screen Wake Lock while running (re-requested on `visibilitychange`, since the browser drops it whenever the tab is hidden). Created by `AppComponent` purely for those side effects.
- [`ThemeService`](src/app/services/theme.service.ts) — dark mode as a signal, persisted via `StorageService`, applied by toggling a `dark` class on `document.body` inside an `effect()`. With nothing stored it starts from `prefers-color-scheme`; the in-app toggle takes over from its first use.

`TimerService`, `ThemeService` and the settings form depend on [`StorageService`](src/app/services/storage.service.ts), a thin JSON-serializing wrapper around `@capacitor/preferences` (works in both the browser build and the native Capacitor app).

**Domain model and constants** live in [`src/app/models/pomodoro.model.ts`](src/app/models/pomodoro.model.ts), which also holds all Spanish UI copy: `PomodoroSettings` (durations, `autoStartBreaks`/`autoStartWork`, `alertSound`/`alertNotification`, `soundVideoId`), `DEFAULT_SETTINGS`, the `HISTORY_LIMIT` that caps the persisted history, timer presets (`PRESETS`), rest-break copy (`REST_IDEAS`), phase labels (`PHASE_LABELS`), end-of-phase notification copy (`PHASE_ALERTS`), the countdown headline (`headlineFor()`), the keyboard-shortcut legend (`SHORTCUTS`), and `extractYouTubeId()` — a pure function that validates/normalizes a pasted YouTube URL or bare ID into a video ID (used for the background-sound video setting, embedded via `youtube-nocookie.com` with `DomSanitizer.bypassSecurityTrustResourceUrl`).

**Home page composition**: `HomePage` (the `/home` route component) is a shell with no timer state of its own. It owns the global keyboard shortcuts (Space = start/pause, S = skip, R = reset, T = toggle theme, 1–4 = apply preset), renders both layouts (only one is visible — the breakpoint switch is the entire content of `home.page.scss`), and swaps in the break overlay while `timer.isBreak()`. It also carries the page's one `aria-live` region (`liveStatus` — phase and running state only, since announcing the seconds would drown out everything else) and the history `ion-modal`. Its children live under `src/app/home/components/`:

- `home-header` — toolbar (cycle counter, history, theme toggle, link to settings). The history button carries `id="open-history"` and no click handler: the modal itself lives in `home.page.html`, and Ionic's `trigger` wires the two together across component boundaries.
- `panel-compact` — the single-column layout used below the desktop breakpoint. It is a *stack* of cards (timer, presets, sound), not a single one.
- `panel-main` / `panel-side` — the two desktop panels (title + task + ring + controls; sound, presets, cycle progress and the day's totals). `panel-main` is also the container the fluid sizes below resolve against.
- `break-overlay` — full-window takeover shown during a break. It is created fresh each break, which is what picks the first `REST_IDEAS` suggestion. It behaves as a modal dialog: `role="dialog"`/`aria-modal`, focus moved to the first action on init, Escape ends the break, and `home.page.html` marks the header and `ion-content` behind it `inert`. That attribute goes on those two elements rather than on a wrapper `div`, because `ion-content` has to stay a direct child of the page to size itself.
- `period-history` — the completed-period list, shown inside the history modal, with the day's totals on top and a confirmed "vaciar historial".

**Never bind an `aria-*` attribute on an Ionic component.** `[attr.aria-label]="…"` on an `ion-button` throws `Cannot read properties of undefined (reading 'onAriaChanged')`: Ionic's `attributeChangedCallback` reaches for a lazy instance that does not exist yet when Angular writes the attribute during the first render. The exception aborts that render, and the page is left half-hydrated — Ionic's vdom then fails on every component (`createElementNS('[object Object]')`) and no icon loads (`Failed to construct 'URL'`). Keep `aria-label` static on Ionic elements; a control's accessible name should describe what it does rather than what state it is in, and the icon carries the state. Dynamic `[attr.*]` on *native* elements (the preset tiles' `aria-pressed`) is fine.

Components inject `TimerService`/`ThemeService` directly instead of taking `@Input()`s. That only works without duplication because the derived values live in the service: when a component needs a new one, add a `computed()` to `TimerService` rather than a getter in the component.

**Shared presentational pieces** live in [`src/app/shared/`](src/app/shared/) (`SharedModule`, imported by feature modules): `app-progress-ring` (SVG countdown ring, takes `progress` and a `compact`/`panel` variant, projects its centre content), `app-progress-dots` (cycle dots, projects extra content), `app-timer-controls` (start/pause/skip/reset, `showLabels` input), `app-preset-grid` (the one-tap duration tiles), `app-sound-player` (the YouTube embed, `fill`/`fixed` variant), `app-task-input` (the "what are you working on" label, committed on `ionChange` so storage is written once per edit rather than once per keystroke) and the `mmss` pipe — exported as a plain `formatMmss()` too, for the document title, which is written from a service where a pipe cannot reach.

The preset grid, the sound player and the task input are shared rather than owned by the desktop sidebar precisely because both layouts show them: the phone has no keyboard shortcuts to fall back on, so anything that reaches only the desktop panels is missing outright there.

The ring's 1s `stroke-dashoffset` transition exists to make a tick look continuous. A reset, a skip or a phase change moves the arc all at once, so `ProgressRingComponent` compares each new `progress` with the previous one and drops the transition when the change is larger than a tick could produce.

**Styling conventions**: the app is themed on the Ionic design system, and [`src/theme/variables.scss`](src/theme/variables.scss) is where that lives. It declares a *full* Ionic palette in the app's navy/platinum hues — the semantic colours (`primary`/`secondary`/`tertiary`/`medium`/`light`/`dark` with their `-rgb`/`-contrast`/`-shade`/`-tint` companions) plus the `--ion-background-color-step-*` and `--ion-text-color-step-*` ramps. The ramps are not optional decoration: Ionic 9 components resolve their own borders, placeholders, notes, disabled states and ripples against them, so omitting them makes native components fall back to Ionic's stock grey scale and drift off-palette. Everything else the app needs (spacing, type sizes, radii, the `--shadow-1` elevation, control height, ring geometry) is declared alongside, and the `--color-*` tokens components actually reference are thin **aliases** over the Ionic ones (`--color-accent: var(--ion-color-primary)` and so on).

Those aliases are emitted by the `app-aliases` mixin into *both* `:root` and `body.dark`, not inherited from `:root`. A custom property whose value is `var(--x)` is substituted where it is declared, not where it is used, so an alias declared once on `:root` would keep the light value forever inside `body.dark`. Any new token defined in terms of another belongs in that mixin.

Dark mode stays manual (`body.dark`, driven by `ThemeService`) rather than Ionic's `dark.class.css` palette file, so it follows the in-app toggle instead of the OS preference.

Breakpoints cannot be custom properties, so they are Sass variables in [`src/theme/_breakpoints.scss`](src/theme/_breakpoints.scss) (`@use '.../breakpoints' as bp;`). [`src/global.scss`](src/global.scss) is limited to Ionic's base CSS, a few reused utility classes (`.eyebrow`, `.hr`/`.divider-tight`, `.tabular-nums`, `.run-dot`) and a deliberately thin set of Ionic component defaults — *shape only* (radii, elevation), since colour reaches those components through the palette. Component stylesheets should reference tokens rather than raw values.

The visual grammar is Ionic's: rounded surfaces separated by elevation instead of rules (hence a single `--rule-hairline` and no thick rule), the Ionic system font stack rather than a webfont, and native components wherever one fits — `ion-card` for the sidebar blocks and the compact timer, an `inset` `ion-list` for the history and the settings groups, `ion-chip` for status metadata, `ion-badge` for the phase, `ion-toggle` for the dark-mode row, and `ion-ripple-effect` on the preset tiles.

**Fluid sizing on the desktop panels**: `.panel-main` declares `container-type: inline-size` / `container-name: panel-main`, and everything that grows with the window — the title, the countdown, the `%` label and `--ring-size-panel` — is sized in container units (`cqi`) against it, not in `vw`. Viewport units are wrong here: `.panel-side` holds a fluid fixed width (`clamp(var(--sidebar-min-width), 26vw, 42rem)`) rather than a flex share, so the main panel's width is *window minus sidebar* and `vw` overflows it on narrow desktops. Where a size could also outgrow the panel's height, the clamp takes a `min()` with a `vh` term (`min(40cqi, 56vh)`) so a wide-but-short window shrinks it instead of pushing the controls off-panel. The `panel` ring variant is only ever rendered inside this container — `cqi` in `--ring-size-panel` would resolve against the viewport anywhere else.

**Settings page**: `SettingsPage` edits a local copy of `PomodoroSettings` (`form`) and only commits it via `timer.updateSettings()` on explicit save, clamping numeric fields to be positive integers. The notification toggle is the one control that is not bound two-way: enabling it needs the browser's permission, the request has to come from a user gesture, and the value is written back only once the answer is in — `notificationsBlocked` then explains a refusal rather than letting the toggle silently spring back.

## Platform targets

- The web build is an installable, offline-capable PWA: [`src/manifest.webmanifest`](src/manifest.webmanifest) (listed in the `angular.json` assets) plus a service worker configured in [`ngsw-config.json`](ngsw-config.json) and registered by `AppModule` with `enabled: !isDevMode()`, so it never gets in the way of `ng serve`. The icons are SVG at `sizes: "any"` rather than a ladder of PNGs — one file covers every size a launcher or a tab asks for. `start_url`/`scope` are relative (`.`) so the GitHub Pages deploy under `/pomodoro-app/` resolves them correctly.
- Web build output (`www/`) is deployed to GitHub Pages from `main` via GitHub Actions.
- `android/` is a generated Capacitor native project (`capacitor.config.ts` sets `webDir: 'www'`) — run `npx cap sync android` after a web build if native platform files need updated web assets.
